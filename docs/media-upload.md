# بارگذاری عکس و فیلم در ای‌پلاک (اپ، سایت و پنل مدیریت)

این سند «کل مسیر عکس و فیلم» را توضیح می‌دهد: از لحظه‌ای که شهروند با دوربین گوشی
عکس/فیلم می‌گیرد تا وقتی کارشناس شهرداری آن را در پنل مدیریت می‌بیند.

---

## ۱. مشکل قبلی چه بود؟ (ریشه‌ی خرابی)

قبلاً بارگذاری عکس و فیلم «ظاهری» بود و در واقع هیچ فایلی به سرور نمی‌رفت:

| ریشه‌ی مشکل | توضیح |
|---|---|
| نبود اندپوینت آپلود | هیچ مسیر سروری برای دریافت فایل وجود نداشت؛ فقط نام فایل در مرورگر ذخیره می‌شد |
| نبود جدول دیتابیس | جدول `media` در دیتابیس نبود و فایل آپلودشده جایی ثبت نمی‌شد |
| نبود دوربین داخل اپ | وب‌ویو اندروید `onShowFileChooser` را پیاده‌سازی نکرده بود؛ دکمه‌ی انتخاب فایل هیچ واکنشی نداشت |
| آدرس سرور سخت‌کد | آدرس API روی یک IP محلی ثابت بود و در گوشی واقعی کار نمی‌کرد |
| فشرده‌سازی/اعتبارسنجی سمت اپ | عکس‌های چند ده مگابایتی گوشی بدون فشرده‌سازی، نیمه‌کاره رها می‌شدند |

اکنون همه‌ی این مسیرها ساخته و آزمون شده‌اند (بخش ۷).

---

## ۲. معماری مسیر فایل

```
گوشی کاربر / مرورگر
   │  ۱) عکس/فیلم گرفتن (دوربین داخلی اپ، دوربین سیستمی یا گالری)
   ▼
core/media.js   (موتور سمت کاربر)
   │  • فشرده‌سازی عکس (حداکثر ۱۹۲۰px، کیفیت ۰٫۸۲)
   │  • تشخیص نوع/حجم پیش از ارسال + پیام فارسی روشن
   │  • آپلود با درصد پیشرفت، تلاش مجدد خودکار
   │  • صف آفلاین (IndexedDB): اگر اینترنت قطع بود، بعداً خودش می‌فرستد
   ▼
POST api/media.php  (multipart/form-data)
   │  • تشخیص نوع فایل با «امضای بایتی» (نه پسوند، نه هدر مرورگر)
   │  • ذخیره در uploads/media/YYYY/MM/<نام تصادفی>.<پسوند>
   │  • ثبت رکورد در جدول media (مالک، نوع، حجم، طول فیلم، توکن)
   ▼
POST api/reports.php  ← ثبت گزارش (و اتصال رسانه‌ها)
   │  • media_ids → UPDATE media SET report_id = …
   ▼
مشاهده: پنل مدیریت (admin/report_detail.php) + جزئیات گزارش در اپ
```

نکته‌ی مهم: **فایل‌ها هرگز داخل دیتابیس ذخیره نمی‌شوند**؛ فقط اطلاعات آن‌ها در جدول
`media` ثبت می‌شود و خود فایل در پوشه‌ی `uploads/media` می‌ماند (روش استاندارد و سبک).

## ۳. قرارداد API (برای توسعه‌دهنده)

| مسیر | توضیح |
|---|---|
| `POST /api/media.php` | آپلود؛ فیلدهای `phone` (الزامی)، `report_id` (اختیاری)، `source` (`camera`/`gallery`/`upload`)، `duration_ms` (اختیاری) و فایل در `file` یا `files[]` |
| `POST /api/media.php?action=attach` | `{phone, report_id, ids[]}` — اتصال رسانه‌های آپلودشده به گزارش |
| `GET /api/media.php?action=list&phone=…&report_id=…` | فهرست رسانه‌های کاربر/گزارش |
| `GET /api/media.php?action=config` | محدودیت‌های مؤثر (حجم، تعداد، طول فیلم) برای نمایش در اپ |
| `GET /api/media.php?action=file&t=TOKEN[&download=1]` | تحویل فایل با پشتیبانی `Range` (پخش/جست‌وجوی فیلم) |
| `DELETE /api/media.php?id=…&phone=…` | حذف رسانه توسط مالک (رکورد + فایل) |

نمونه‌ی پاسخ آپلود:

```json
{
  "success": true,
  "count": 1,
  "items": [{
    "id": 12, "kind": "image", "mime": "image/jpeg", "name": "IMG_0001.JPG",
    "size": 184320, "width": 1920, "height": 1080, "duration_ms": null,
    "source": "camera", "report_id": 7,
    "url": "https://eplak.ir/uploads/media/2026/10/9f2c…a1.jpg",
    "path": "/uploads/media/2026/10/9f2c…a1.jpg",
    "token": "b194…7c2"
  }],
  "errors": []
}
```

نمونه‌ی آپلود با curl:

```bash
curl -X POST "https://eplak.ir/api/media.php" \
  -F "phone=09123456789" -F "report_id=7" -F "source=camera" \
  -F "files[]=@photo.jpg" -F "files[]=@movie.mp4"
```

### محدودیت‌های پیش‌فرض

| مورد | مقدار پیش‌فرض | محل تغییر |
|---|---|---|
| حجم هر عکس | ۱۲ مگابایت | `media.max_image_bytes` |
| حجم هر فیلم | ۹۶ مگابایت | `media.max_video_bytes` |
| تعداد رسانه‌ی هر گزارش | ۶ | `media.max_count` |
| طول فیلم | ۹۰ ثانیه | `media.max_video_seconds` |
| سقف آپلود ساعتی هر شماره | ۱۲۰ | `media.hourly_limit` |
| فرمت‌های مجاز | عکس: JPG/PNG/WEBP/GIF/HEIC/AVIF — فیلم: MP4/MOV/WEBM/3GP | `shared/media.php` |

## ۴. راه‌اندازی سمت سرور (مهم)

### ۴.۱ سقف بارگذاری PHP

سرور به‌صورت پیش‌فرض اجازه‌ی فایل‌های بزرگ نمی‌دهد. در cPanel → **MultiPHP INI Editor**
(یا `php.ini` سرور) این مقادیر را تنظیم کنید:

```ini
upload_max_filesize = 100M
post_max_size       = 120M
max_file_uploads    = 20
max_execution_time  = 300
```

اگر این کار انجام نشود، سرور فیلم‌های بزرگ را با خطای **۴۱۳** رد می‌کند؛ اپ این سقف را
از `api/media.php?action=config` می‌خواند و پیش از ارسال، پیام فارسی واضح نشان می‌دهد
(«حجم فیلم از سقف سرور بیشتر است…»). تنظیمات رسانه در `shared/config.php`:

```php
'media' => [
    'max_image_bytes'   => 12 * 1024 * 1024,
    'max_video_bytes'   => 96 * 1024 * 1024,
    'max_count'         => 6,
    'max_video_seconds' => 90,
    'hourly_limit'      => 120,
    'public'            => true,     // اگر پوشه‌ی uploads از وب قابل دسترسی نیست: false
],
```

### ۴.۲ پوشه‌ی آپلود

پوشه‌ی `uploads/media` خودکار ساخته می‌شود و باید توسط PHP قابل نوشتن باشد:

```bash
mkdir -p uploads/media && chmod -R 775 uploads
```

داخل این پوشه فایل `.htaccess` خودکار ساخته می‌شود که **اجرای هر اسکریپتی** را می‌بندد
(دفاع در برابر آپلود فایل PHP/Javascript). این پوشه در گیت نیست (`.gitignore`) و
فایل‌های کاربران اشتباهاً کامیت نمی‌شوند.

### ۴.۳ دیتابیس

جدول `media` در `shared/bootstrap.php` **خودکار** ساخته/ارتقا می‌یابد (هم MySQL و هم
SQLite). اگر دیتابیس را دستی می‌سازید، جدول در `backend/eplak_db.sql` هم اضافه شده است.

## ۵. اپ اندروید

| موضوع | توضیح |
|---|---|
| دسترسی‌ها | `CAMERA`، `RECORD_AUDIO`، `READ_MEDIA_IMAGES/VIDEO` (اندروید ۱۳+) در `AndroidManifest.xml` |
| انتخاب فایل | `MainActivity.kt` متد `onShowFileChooser` را پیاده کرده؛ دکمه‌های گالری/دوربین سسیستم باز می‌شوند |
| دوربین داخل اپ | صفحه از `https://appassets.androidplatform.net` سرو می‌شود (زمینه‌ی امن) تا `getUserMedia` + `MediaRecorder` کار کند؛ اگر دستگاه پشتیبانی نکند، خودکار به دوربین سیستمی برمی‌گردد |
| آدرس سرور | از پل `AndroidApp.getApiBaseUrl()` (مقدار `api_base_url` در `strings.xml`) خوانده می‌شود؛ اگر خالی باشد، اپ از کاربر می‌پرسد و در حافظه ذخیره می‌کند |

برای تغییر آدرس سرور در اپ، مقدار `api_base_url` را در
`android-app/app/src/main/res/values/strings.xml` بگذارید:

```xml
<string name="api_base_url">https://eplak.ir/eplak-fixed/api</string>
```

## ۶. حالت آفلاین (صف ارسال)

اگر کاربر در جایی بدون اینترنت عکس/فیلم بگیرد:

1. فایل‌ها در **IndexedDB** با کلید `eplak_media_db` ذخیره می‌شوند (بایت‌های فایل، نه
   مسیر موقت — تا بعد از بستن اپ هم باقی بمانند).
2. با رویداد `online` یا بارگذاری بعدی اپ، صف خودکار تخلیه می‌شود و رسانه‌ها به گزارشِ
   همان کاربر متصل می‌شوند (`api/media.php?action=attach`).
3. روی آیکون/شمارنده‌ی «در صف ارسال» تعداد فایل‌های معطل نمایش داده می‌شود.

## ۸. عیب‌یابی سریع

| نشانه | علت احتمالی | راه‌حل |
|---|---|---|
| «شماره موبایل معتبر الزامی است» | کاربر وارد نشده یا شماره با فرمت `+98` ذخیره شده | یک‌بار ورود/خروج؛ شماره‌ها خودکار به `09xxxxxxxxx` تبدیل می‌شوند |
| خطای ۴۱۳ یا «حجم از سقف سرور بیشتر است» | `post_max_size`/`upload_max_filesize` کم است | بخش ۴.۱ |
| «نوع فایل قابل تشخیص نیست» | فایل واقعاً عکس/فیلم نیست (تغییر پسوند) یا HEIC ناشناخته | فایل اصلی را از گالری انتخاب کنید؛ HEIC پشتیبانی می‌شود |
| «ساخت پوشه‌ی رسانه ممکن نشد» | دسترسی نوشتن `uploads/` | بخش ۴.۲ |
| دکمه‌ی دوربین در اپ کار نمی‌کند | دسترسی دوربین داده نشده | تنظیمات اندروید → مجوزها → دوربین؛ سپس اپ را دوباره باز کنید |
| فایل آپلود می‌شود ولی در پنل دیده نمی‌شود | گزارش به‌درستی ساخته نشده یا کش مرورگر | `admin/report_detail.php?id=…` را مستقیم باز کنید |
| عکس در اپ دیده می‌شود ولی در پنل نه | مقدار `media.public` را `false` نکرده‌اید ولی پوشه از وب باز نیست | `'public' => true` یا `public_url` را تنظیم کنید |
