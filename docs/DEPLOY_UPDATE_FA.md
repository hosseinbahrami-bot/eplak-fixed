# راهنمای به‌روزرسانی سایت (eplak.ir/eplak-fixed)

این راهنما برای وقتی است که کد جدید را روی هاست آپلود می‌کنید تا
تغییرات پنل ادمین و اپ **روی سایت اصلی** دیده شود.

---

## ۱) فایل‌هایی که باید آپلود شوند

اگر از فایل `eplak-fixed-update.zip` استفاده می‌کنید، همه‌ی فایل‌های لازم داخلش هست؛
کافی است محتوایش را در ریشه‌ی `eplak-fixed/` روی هاست «Extract» کنید.

فایل‌های اصلی این به‌روزرسانی:

**فایل‌های تازه (جدید):**
- `shared/webpush.php` — موتور اعلان پس‌زمینه
- `shared/media.php` — ذخیره‌سازی عکس و فیلم گزارش‌ها
- `api/push.php` — اندپوینت‌های اعلان
- `api/media.php` — سرو امن فایل‌های پیوست
- `.htaccess` — تنظیمات کش و امنیت (پایین توضیح داده شده)
- `shared/notification_reads.php` — ثبت «کدام کاربر اعلان را خوانده است» (وضعیت خوانده‌شده به‌ازای هر کاربر)

**فایل‌های تغییر‌یافته:**
- `shared/bootstrap.php` — همگام‌سازی خودکار ساختار دیتابیس (رفع خطای `send_id`)
- `admin/settings.php` — تغییر نام کاربری/رمز + بخش ساختار دیتابیس + تست اعلان
- `admin/includes/functions.php` · `admin/report_detail.php` · `admin/reports.php`
  · `admin/news.php` · `admin/news_add.php` · `admin/news_edit.php`
  · `admin/notifications.php` · `admin/index.php` · `admin/assets/style.css`
- `api/reports.php` · `api/news.php` · `api/notifications.php` (وضعیت خوانده‌شدن هر کاربر)
- `admin/notification_view.php` · `admin/notifications.php` (نمایش درست خوانده‌شده/نخوانده)
- `android-app/.../NotificationBridge.kt` + `MainActivity.kt` + `AndroidManifest.xml` (اعلان سیستمی گوشی)
- `index.html` · `app.js` · `sw.js`
- `core/storage.js` · `core/i18n.js`
- `modules/reports.js` · `modules/live.js` · `modules/dashboard.js`
- `router_admin.php`

> **مهم:** پوشه‌های `data/` و `uploads/` و فایل `shared/config.php` روی هاست شما
> وجود دارند و نباید پاک شوند (دیتابیس و تنظیمات و فایل‌های آپلودی شهروندان).

## ۲) روش آپلود (cPanel)

1. وارد **cPanel → File Manager** شوید و به پوشه‌ی `public_html/eplak-fixed` بروید.
2. **قبل از هر کار یک نسخه‌ی پشتیبان بگیرید:** روی پوشه‌ی `eplak-fixed` راست‌کلیک →
   `Compress` → یک فایل zip بسازید و دانلودش کنید (یا از `Backup Wizard` استفاده کنید).
3. فایل `eplak-fixed-update.zip` را در همان پوشه Upload کنید.
4. راست‌کلیک روی فایل → **Extract** → روی `Overwrite existing files` تأکید کنید.
5. فایل zip را پاک کنید.
6. مطمئن شوید پوشه‌ی `uploads` وجود دارد و دسترسی‌اش `755` است
   (اگر نبود، خودش ساخته می‌شود؛ فقط باید قابل نوشتن باشد).

### روش جایگزین: Git (اگر در cPanel فعال است)
اگر در cPanel بخش **Git™ Version Control** دارید و ریپو را به هاست وصل کرده‌اید،
کافی است در همان صفحه دکمه‌ی **Pull or Deploy** را بزنید.

---

## ۳) بعد از آپلود (سه قدم کوتاه)

1. **ترمیم خودکار دیتابیس:** یک‌بار وارد پنل شوید
   (`https://eplak.ir/eplak-fixed/admin/login.php`).
   کد جدید خودش ستون‌های تازه (مثل `notifications.send_id`) را به دیتابیس اضافه می‌کند.
   برای اطمینان: **تنظیمات پنل → ساختار دیتابیس → دکمه‌ی «بررسی و ترمیم ساختار دیتابیس»**.
2. **کش مرورگر:** در اپ/سایت یک‌بار صفحه را با `Ctrl+F5` (یا در گوشی: بستن کامل اپ و باز کردن دوباره)
   تازه کنید. فایل `.htaccess` جدید کاری می‌کند که از این به بعد
   `index.html` و فایل‌های JS کش نشوند و تغییرات بعدی فوراً دیده شوند.
3. **امتحان اعلان:** روی یک گوشی اپ را باز کنید و اجازه‌ی اعلان را تأیید کنید،
   سپس در **تنظیمات پنل → ارسال اعلان آزمایشی** شماره را وارد کنید و بزنید.

---

## ۴) نکته‌ی `.htaccess`

فایل `.htaccess` سه کار می‌کند:
- صفحات (`.html` و `.php`) کش نمی‌شوند → **تغییرات پنل و اپ بلافاصله روی سایت دیده می‌شود**
- `sw.js` همیشه تازه بررسی می‌شود → نسخه‌ی جدید اعلان‌ها فعال می‌شود
- دسترسی مستقیم مرورگر به پوشه‌های داخلی (`shared/`, `data/`, `admin/includes/`) بسته می‌شود

اگر بعد از آپلود سایت **خطای 500** داد (یعنی هاست اجازه‌ی برخی دستورها را نمی‌دهد)،
فقط این فایل را موقتاً تغییر نام دهید:
`File Manager → .htaccess → Rename → .htaccess.off`
سایت بلافاصله برمی‌گردد و بقیه‌ی تغییرات سر جای خودشان هستند.

---

## ۵) درباره‌ی اپ اندروید

اپ اندروید فایل‌های سایت را به‌صورت **بسته‌بندی‌شده در خودش** دارد
(`file:///android_asset/index.html`). بنابراین آپلود روی هاست، **داخل اپ نصب‌شده** اثر نمی‌گذارد
و برای دیدن تغییرات در اپ باید **فایل APK دوباره ساخته و نصب شود**:

1. پوشه‌ی `android-app/app/src/main/assets/` را از همین پروژه به‌روز کنید
   (فایل‌های `index.html`، `sw.js`، پوشه‌های `core/`، `modules/`، `assets/`).
2. با Android Studio گزینه‌ی `Build → Build Bundle(s) / APK(s) → Build APK(s)` را بزنید.
3. APK تازه را روی گوشی نصب کنید (نسخه‌ی قبلی را حذف/به‌روزرسانی کنید).

> در خود اپ هم آدرس API روی `https://eplak.ir/eplak-fixed/api` تنظیم شده است،
> پس داده‌ها (اخبار، دانستنی‌ها، گزارش‌ها، اعلان‌ها) از همان سایت خوانده می‌شود.

## ۶) اعلان‌ها — چه چیزی کجا می‌رسد؟ (مهم)

| حالت | نتیجه |
|---|---|
| **داخل اپ، وقتی برنامه باز است** | اعلان در فهرست اعلان‌های اپ دیده می‌شود + یک بنر بالای صفحه + صدای اعلان + نوتیفیکیشن در نوار اعلان گوشی |
| **اپ در پس‌زمینه یا صفحه قفل** | نوتیفیکیشن در نوار اعلان گوشی نمایش داده می‌شود (از طریق خود اندروید) |
| **اپ کاملاً بسته** | ✅ با فایربیس (FCM) — راه‌اندازی یک‌باره (بخش ۶-۳) |
| **سایت در مرورگر کروم گوشی** | اعلان روی صفحه‌ی قفل هم می‌رسد (مناسب‌ترین راه فعلی) |

### ۶-۱) چرا در اپ اندروید «اعلان پس‌زمینه‌ی مرورگر» کار نمی‌کند؟
اپ اندروید، سایت را داخل یک WebView نشان می‌دهد. اندروید در WebView دو قابلیت را
پیاده‌سازی **نکرده** است: `Push API` و `Notification API`
(مرجع: جدول سازگاری MDN — ستون WebView Android برای PushManager: “No support”).
به همین دلیل نوتیفیکیشن در اپ از مسیر خودِ اندروید نمایش داده می‌شود (فایل
`NotificationBridge.kt`). لازم است APK دوباره ساخته و نصب شود (بخش ۵).

### ۶-۲) فعال کردن اعلان برای شهروندان (بدون کار فنی)
۱. سایت را در **مرورگر کروم** گوشی باز کند: `https://eplak.ir/eplak-fixed`
۲. از منوی مرورگر → **افزودن به صفحه اصلی**
۳. اپلیکیشن اضافه‌شده را باز کند و اجازه‌ی اعلان را **تأیید** کند
در صفحه‌ی «اعلان‌ها»ی اپ، وضعیت اعلان همین دستگاه نشان داده می‌شود و اگر
اجازه داده نشده باشد، دکمه‌ی **«فعال‌سازی اعلان»** ظاهر می‌شود.

### ۶-۳) اعلان در حالت «کاملاً بسته» — فایربیس (در کد پیاده‌سازی شد ✅)
> 📘 **آموزش گام‌به‌گام کامل با تصویرِ مراحل و عیب‌یابی: `docs/FIREBASE_SETUP_FA.md`**
> (فارسی) — نسخه‌ی انگلیسی: `docs/FIREBASE_SETUP_EN.md`

خلاصه‌ی مراحل:

**الف) پروژه‌ی رایگان فایربیس بسازید**
1. <https://console.firebase.google.com> → **Add project** (مثلاً به نام `eplak`).
2. داخل پروژه → آیکن **Android** → نام بسته را دقیقاً `com.example.eplakfixed` بگذارید → **Register app**.
3. فایل **`google-services.json`** را دانلود کنید.

**ب) فایل را در پروژه بگذارید (تا APK با فایربیس ساخته شود)**
فایل را در مسیر `android-app/app/google-services.json` قرار دهید و به گیت‌هاب پوش کنید
(از خود سایت گیت‌هاب هم می‌توانید Upload کنید). به‌محض پوش شدن، ساخت APK
خودکار انجام می‌شود و APK تازه **با اعلان فایربیس** آماده می‌شود.

**ج) کلید سرویس را در پنل ادمین بگذارید (برای ارسال از سرور)**
1. Firebase → ⚙️ **Project settings** → تب **Service accounts** → **Generate new private key**.
2. پنل ادمین → **تنظیمات** → بخش **«اعلان گوشی برای اپ اندروید (فایربیس)»** →
   محتوای کامل فایل JSON را بچسبانید → **ذخیره و بررسی اتصال**.
3. پیام «✅ کلید سرویس ذخیره شد و اتصال به گوگل برقرار است» یعنی آماده است.
4. با **ارسال آزمایشی فایربیس** یک اعلان به گوشی خود بفرستید (گوشی قفل یا اپ بسته).

> ⚠️ فایل کلید سرویس محرمانه است؛ فقط در پنل ادمین وارد می‌شود و در `.gitignore` مسدود شده است.

### ۶-۴) دانلود و نصب APK تازه (بدون Android Studio)
**لینک ثابت دانلود:**
`https://github.com/hosseinbahrami-bot/eplak-fixed/releases/download/v2.0-eplak-update/eplak-app.apk`

یا صفحه‌ی Releases → بخش Assets → `eplak-app.apk`

نصب: دانلود روی گوشی → اجازه‌ی «نصب از منابع نامشخص» → نصب.
اگر پیام «App not installed» دیدید، نسخه‌ی قبلی اپ را پاک کنید و دوباره نصب کنید.

### ۶-۵) ساخت APK پس از هر تغییر (خودکار)
با هر تغییر در فایل‌های اپ/سایت، ورک‌فلوی `.github/workflows/android-apk.yml`
خودش APK را می‌سازد: **Actions → Build Android APK → آخرین اجرا → Artifacts → `eplak-apk`**
(یا از همان لینک Releases). کلید امضای اپ کش می‌شود تا نسخه‌های بعدی روی
نسخه‌ی نصب‌شده به‌راحتی نصب شوند.

## ۷) چک‌لیست سریع بعد از به‌روزرسانی

- [ ] `https://eplak.ir/eplak-fixed/` باز می‌شود و نسخه‌ی جدید اپ لود می‌شود
- [ ] `https://eplak.ir/eplak-fixed/admin/login.php` → ورود با نام کاربری/رمز
- [ ] **تنظیمات پنل**: تغییر نام کاربری و رمز کار می‌کند (بعدش با اطلاعات جدید وارد شوید)
- [ ] **اخبار و دانستنی‌ها**: یک مورد اضافه/ویرایش کنید و در سایت ببینید
- [ ] **گزارش‌ها**: یک گزارش با عکس بفرستید و در پنل → جزئیات گزارش عکس را ببینید
- [ ] **اعلان آزمایشی**: از تنظیمات پنل برای گوشی خودتان بفرستید
- [ ] **وضعیت خوانده شدن:** در اپ یک اعلان را باز کنید → پنل → اعلان‌ها → آیکن چشم (مشاهده گیرندگان) → باید «خوانده شده» نشان دهد
- [ ] اگر خطایی دیدید: `admin → تنظیمات → وضعیت فنی سرور` و بخش «ساختار دیتابیس»

### ۷) آزمون‌های خودکار (برای اطمینان قبل از هر تغییر)
قبل از اینکه تغییری روی هاست بگذارید، می‌توانید همه‌ی آزمون‌ها را روی کامپیوتر
خودتان اجرا کنید (بدون نیاز به سرور، MySQL یا Android Studio):

```bash
bash tools/dev/run-regression.sh          # همه‌ی آزمون‌ها
bash tools/dev/run-regression.sh fcm      # فقط آزمون فایربیس
bash tools/dev/run-regression.sh syntax   # فقط بررسی نحوی فایل‌ها
```

این آزمون‌ها چه چیزهایی را بررسی می‌کنند؟
- **syntax** — همه‌ی فایل‌های PHP و JS از نظر نحوی سالم‌اند (بدون خطای سفید صفحه).
- **notify** — «خوانده شدن» اعلان برای هر کاربر جداگانه ثبت می‌شود و آمار پنل درست است.
- **app** — درخواست‌های خود اپ: گزارش «خوانده شد»، اعلان سیستمی اندروید، ثبت توکن فایربیس.
- **pushcrypto** — رمزنگاری اعلان مرورگر و امضای VAPID (تأیید ریاضی کلیدها).
- **fcm** — موتور فایربیس: ساخت توکن گوگل، ارسال پیام، غیرفعال‌سازی خودکار توکن باطل.
- **backend** — ساخت جدول‌ها، بذرها، آپلود عکس، ساختار خودترمیم دیتابیس قدیمی و صفحات پنل.

همین آزمون‌ها در گیت‌هاب هم به‌صورت خودکار اجرا می‌شوند:
**GitHub → تب Actions → «آزمون‌های خودکار (Regression)»**.

### ۸) بررسی اینکه تغییرات روی سایت اعمال شده یا نه
دو راه ساده دارید:

**راه اول (داخل پنل):** بعد از آپلود بسته، در پنل ادمین منوی **«بررسی نسخه»**
(`ادمین → بررسی نسخه`) را باز کنید. اگر همه‌ی نشانه‌ها «درست/هست» بودند، یعنی
همه‌چیز روی هاست درست جا افتاده است. اگر چیزی «نیست» بود، یعنی فایل‌های آن
موجود نیستند و باید بسته دوباره و کامل‌تر Extract شود.

**راه دوم (بدون ورود به پنل، خودکار):** در گیت‌هاب →
**Actions → «بررسی سایت زنده» → Run workflow**. ربات سایت شما را از بیرون
می‌خواند و نتیجه را در Issue با عنوان «گزارش بررسی سایت زنده (eplak.ir)» می‌نویسد.
همچنین می‌توانید روی کامپیوتر خودتان اجرا کنید:

```bash
bash tools/live-check.sh https://eplak.ir/eplak-fixed
```
